The Work Pipeline

Auto step — chains without pause in fast mode
Gate — always pauses for your approval
Parallel block — multiple agents at once
Optional / conditional step
00
Intake — Stage 0.5 Auto

Captures everything the pipeline needs before any artifact is produced. The skill asks 7 questions: feature name, Jira project, Jira ticket conventions (open-ended probe with examples — labels, title format, BE/FE split, custom field defaults, fields to leave blank, link conventions), tech stack, product type, permission model, and backend/API surface. Answers persist to _pipeline-state.json → intake and are read by downstream steps. If a prior feature exists in the workspace, the skill offers to reuse its intake.

📁 _pipeline-state.json → intake
📄 subprompts/build-product.md — Stage 0.5

Research Idea Auto

Interactive discovery (15-dimension checklist), knowledge-base check against past features, web scan for market context and prior art.

02
Codebase Review Auto

Point at folder paths on disk. The skill reads the folder structure, samples representative files, and produces a handoff summary with rated risks — feeds directly into Step 3 (PRD) and Step 4b (Technical Review).

📁 codebase-review/[feature]-codebase-review.md
03
Create PRD Auto

Generates an 11-section PRD seeded by research + codebase handoff. Scoping-aware (roles, API surface, product type). Auto-linted against your style preferences before saving. Decision Log pre-populated from knowledge base.

📁 prd/[feature]-prd.md
4a
4b
Dual Review Parallel

Two isolated sub-agents (Claude Agent tool) run simultaneously — not role-switching. 4a Product Reviewer: document quality, problem-solution fit, UX gaps, missing states. 4b Technical Reviewer: reads both the PRD and the codebase review — architecture, data model, API contracts, security, HIGH risks.

Results synthesized: agreements applied, single-source findings logged, conflicts converted to conflict cards for Gate 1.

📁 product-review/ + technical-review/
G1
Apply Fixes → Gate 1: PRD Approval Gate
⏸ Pipeline pauses here. Review the PRD. Say "approved" or give feedback.

Applies all review findings to the PRD. Then runs ~5 automated quality checks before presenting the gate: problem statement specificity, measurable outcomes, HIGH risks resolved, success metric baseline, codebase risk coverage. Conflict cards must be resolved.

Supports conditional approval. Say "approved with conditions: [list]" to advance now and track conditions in _open-conditions.md — verified at Gate 2.

📁 prd/[feature]-prd.md (updated in place)
📄 Context checkpoint written to _context-checkpoint.md
06
System Design Optional

Only if you answered "yes" to complex architecture at Gate 1. Generates a full system design doc: overview, architecture diagram, data structures, APIs, feature-by-feature implementation plan, build order, open technical decisions.

📁 technical-review/[feature]-system-design.md
07
Visual Diagram Auto

Creates a visual diagram of the feature: user journey map, system architecture, or wireflow. Primary: Figma FigJam via Figma MCP — generates a shareable Figma file, stores URL in state. Fallback: Mermaid syntax (with a warning that it won't render in Confluence without a plugin).

📁 diagrams/[feature]-feature-diagram.md
🔗 Figma URL → _pipeline-state.json → export_urls.figma_diagram_url
08
Design Prompts — v0 / Figma Make Auto

Generates one structured design prompt per screen. The same prompt works in both v0 and Figma Make — PM chooses the tool. Prompts include: context, layout, content list, all four states (default, empty, loading, error), and optionally component references for Figma Make. Full screen inventory validated against PRD user stories.

📁 design/[feature]-phase-[N]-designs.md
G2
Update PRD from Designs → Gate 2: Designs Approval Gate
⏸ Pipeline pauses here. Review the design catalog. Say "approved" or give feedback.

Syncs the PRD with the finalized design catalog: design catalog reference, copy/flow changes, AC updates, decision log entries. Quality checks: diagram coverage, UI state coverage (empty/loading/error/populated), Gate 1 conditions resolved.

📁 prd/[feature]-prd.md (updated in place)
G3
User Stories Breakdown → Gate 3: Breakdown Approval Gate
⏸ Pipeline pauses here. Review the breakdown. Once approved, Jira tickets are created.

Generates exhaustive Gherkin acceptance criteria, FE/BE story pairing, testing notes, and a Build Sequence Map. 8 automated quality checks: all PRD stories present, unique US-IDs, ≥2 scenarios per story, edge-case coverage, FE/BE pairs complete, no XL stories without splits, HIGH risks in testing notes, UX state coverage per FE story.

Optional after approval: publish breakdown to Confluence + share in Slack for engineering sizing review before Jira tickets are created.

📁 user-stories/[feature]-user-stories.md
11
Export Parallel

Three parallel export agents. Jira (always): creates Epic + one ticket per user story with ADF user story, verbatim Gherkin AC, Testable field, FE/BE labels, sequence labels (seq-01…), size labels, and Relates-to linking for FE/BE pairs. Deduplication check prevents re-runs from creating duplicates. Drive (optional): mirrors the entire feature folder, generates a _FEATURE_SUMMARY.md. Confluence (optional): publishes or updates the PRD page with Figma diagram embed.

🎫 Jira Epic + tickets
📁 jira-export/[feature]-jira-manifest.md
☁️ Drive folder (if enabled)
📖 Confluence page (if enabled)

Recent Changes

v2.1.0 2026-05-20 MINOR
  • Open-ended Jira conventions at intake. Intake question #3 used to ask only for labels. It now probes — with examples — for every per-ticket convention: labels, title format (verb-first, [BE]/[FE] prefix), BE/FE split rule, custom-field defaults (e.g., Testable Yes/No), fields to leave blank (e.g., Story Points), link conventions.
  • Conventions applied automatically downstream. The user-stories step uses the captured title format. The Jira export step applies labels, custom-field defaults, fields-to-omit, and link conventions when creating tickets.
  • Stage 0.5 — Intake added to the orchestrator. Walks through all 7 intake questions and persists answers to _pipeline-state.json → intake before Step 1. Offers to reuse a prior intake from another feature in the same workspace.
  • No personal CLAUDE.md required. A new team installing the skill no longer has to encode their Jira conventions in a hidden config file.
