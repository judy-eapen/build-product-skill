The Work Pipeline

Auto step — chains without pause in fast mode
Gate — always pauses for your approval
Parallel block — multiple agents at once
Optional / conditional step
00
Intake — Stage 0.5 Auto

Captures everything the pipeline needs before any artifact is produced. The skill asks 7 questions: feature name, Jira project, Jira ticket conventions (open-ended probe with examples — labels, title format, BE/FE split, custom field defaults, fields to leave blank, link conventions), tech stack, product type, permission model, and backend/API surface. Answers persist to _pipeline-state.json → intake and are read by downstream steps. If a prior feature exists in the workspace, the skill offers to reuse its intake.

📄 subprompts/build-product.md — Stage 0.5

Create PRD Auto

Generates an 11-section PRD seeded by research + codebase handoff. Scoping-aware (roles, API surface, product type). Auto-linted against your style preferences before saving. Decision Log pre-populated from knowledge base.

📁 prd/[feature]-prd.md

4b
Dual Review Parallel

Two isolated sub-agents (Claude Agent tool) run simultaneously — not role-switching. 4a Product Reviewer: document quality, problem-solution fit, UX gaps, missing states. 4b Technical Reviewer: reads both the PRD and the codebase review — architecture, data model, API contracts, security, HIGH risks.

Results synthesized: agreements applied, single-source findings logged, conflicts converted to conflict cards for Gate 1.

📁 product-review/ + technical-review/
G1
Apply Fixes → Gate 1: PRD Approval Gate
⏸ Pipeline pauses here. Review the PRD. Say "approved" or give feedback.

Applies all review findings to the PRD. Then runs ~5 automated quality checks before presenting the gate: problem statement specificity, measurable outcomes, HIGH risks resolved, success metric baseline, codebase risk coverage. Conflict cards must be resolved.

Supports conditional approval. Say "approved with conditions: [list]" to advance now and track conditions in _open-conditions.md — verified at Gate 2.

📄 Context checkpoint written to _context-checkpoint.md

System Design Optional

Only if you answered "yes" to complex architecture at Gate 1. Generates a full system design doc: overview, architecture diagram, data structures, APIs, feature-by-feature implementation plan, build order, open technical decisions.

07
Visual Diagram Auto

Creates a visual diagram of the feature: user journey map, system architecture, or wireflow. Primary: Figma FigJam via Figma MCP — generates a shareable Figma file, stores URL in state. Fallback: Mermaid syntax (with a warning that it won't render in Confluence without a plugin).

📁 diagrams/[feature]-feature-diagram.md
🔗 Figma URL → _pipeline-state.json → export_urls.figma_diagram_url
08
Design Prompts — v0 / Figma Make Auto

Generates one structured design prompt per screen. The same prompt works in both v0 and Figma Make — PM chooses the tool. Prompts include: context, layout, content list, all four states (default, empty, loading, error), and optionally component references for Figma Make. Full screen inventory validated against PRD user stories.

📁 design/[feature]-phase-[N]-designs.md
G2
Update PRD from Designs → Gate 2: Designs Approval Gate
⏸ Pipeline pauses here. Review the design catalog. Say "approved" or give feedback.

Syncs the PRD with the finalized design catalog: design catalog reference, copy/flow changes, AC updates, decision log entries. Quality checks: diagram coverage, UI state coverage (empty/loading/error/populated), Gate 1 conditions resolved.

📁 prd/[feature]-prd.md (updated in place)
G3
User Stories Breakdown → Gate 3: Breakdown Approval Gate
⏸ Pipeline pauses here. Review the breakdown. Once approved, Jira tickets are created.

Generates exhaustive Gherkin acceptance criteria, FE/BE story pairing, testing notes, and a Build Sequence Map. Multi-epic grouping (v2.4.0+): proposes an Epic split (one per PRD phase by default, sub-epics for functional clusters); PM accepts or adjusts before stories are composed. DRAFT mode (v2.4.0+): if designs aren't finalized yet, the PM can write stories from the PRD alone — design-dependent stories tagged Status: DRAFT — needs design, sized with *, exempt from UX state coverage at Gate 3, labeled draft in Jira. 9 automated quality checks at Gate 3.

Optional after approval: publish breakdown to Confluence + share in Slack for engineering sizing review before Jira tickets are created.

DRAFT refresh: when designs land later, /change-mode → "Designs arrived" walks through every DRAFT story with the new designs, refreshes AC + sizing + UX coverage, and updates the Jira tickets in place (removes the draft label).

📁 user-stories/[feature]-user-stories.md
10½
Timeline (Gantt) Auto

Produces a Gantt-style timeline at the Epic + Phase level (not story level). Hybrid estimation: the skill proposes durations from the user-stories breakdown's Size column × default velocity (8 person-days per dev per sprint), then the PM tunes any epic or phase. Two outputs every run: Figma FigJam timeline (via Figma MCP — URL stored in _pipeline-state.json) and an interactive HTML Gantt (self-contained, opens offline, hover details per bar, today and target-launch markers, print stylesheet). Honest target-gap math: if the computed end exceeds a PM-supplied target launch, the step surfaces the gap and offers scope cut / team increase / slip — it does not silently shrink durations.

11
Export Parallel

Three parallel export agents. Jira (always): creates one Epic per multi-epic grouping (v2.4.0+) with each Epic's description scoped to its own stories; the PRD + breakdown files attach to every Epic. Then creates one ticket per user story with ADF user story, verbatim Gherkin AC, Testable field, FE/BE labels, sequence labels (seq-01…), size labels, and Relates-to linking for FE/BE pairs. DRAFT stories get a draft label for downstream queryability. Deduplication check prevents re-runs from creating duplicates. Drive (optional): mirrors the entire feature folder, generates a _FEATURE_SUMMARY.md. Confluence (optional, v2.3.0+): publishes the entire feature workspace as a parent hub page + one numbered child page per artifact (Research, Codebase Review, PRD, Product/Technical Review, System Design, Visual Diagram, Design Catalog per phase, User Stories, Timeline). Per-file mtime change detection — only re-publishes pages whose source actually changed.

🎫 Jira Epic + tickets
📁 jira-export/[feature]-jira-manifest.md
☁️ Drive folder (if enabled)
📖 Confluence page (if enabled)
12
Export Conversation Transcript Auto

Reads the live Claude Code session JSONL (~/.claude/projects/-Users-judydarvin/[session-uuid].jsonl) and writes the full PM↔model conversation for this feature's pipeline window to two markdown files. Clean version: user messages + assistant text only — the readable back-and-forth. Full version: same conversation plus tool calls and (truncated) tool results, with system reminders and permission events included for forensic debugging. Model thinking blocks are excluded from both files (private reasoning). Prior transcript exports are timestamp-suffix-renamed rather than overwritten, so every run is preserved. Skippable per-run via "skip transcript" at the end of Step 11; also callable any time via /export-transcript.

📁 transcript/[feature]-transcript-clean.md
📁 transcript/[feature]-transcript-full.md

Recent Changes

v2.4.0 2026-05-21 MINOR
  • Multi-epic support in the User Stories Breakdown. Step 10 proposes an Epic grouping (default: one Epic per PRD phase, sub-epics for clear functional clusters); PM accepts or adjusts. Step 11a Jira Export creates one Jira Epic per group with each Epic's description scoped to its own stories — not the whole PRD. The PRD and User Stories Breakdown files are attached to every Epic so each is self-contained. Existing-Epic detection runs per group so re-runs reuse the right Epics.
  • DRAFT mode for stories without finalized designs. New Step 0.5 design-availability check at Step 10. PM picks: wait, write anyway in DRAFT mode, or cancel. In DRAFT mode, design-dependent stories get Status: ⚠ DRAFT — needs design at the top, sized with * suffix (e.g., M*), exempt from UX state coverage at Gate 3 (reported as known gaps, not failures), and labeled draft in Jira. MIXED mode applies per-phase when only some phases have designs.
  • New /change-mode trigger: "Designs arrived" (seventh trigger type). Reads user_stories.draft_stories[] and the new design catalog, walks through each DRAFT story with the designs in context, refreshes AC + sizing + UX state coverage, and updates the corresponding Jira ticket in place (removes the draft label). When the last DRAFT is cleared, user_stories.mode flips back to full.
  • Step 9 (Update PRD from Designs) now branches on design availability. If designs exist, runs as before. If not, skips the PRD-from-designs sync; Gate 2 becomes a quick "proceed without finalized designs?" confirmation; user_stories.mode is pre-set to DRAFT.
  • State schema: user_stories expanded to an object with mode, epics[], draft_stories[], draft_resolved_at. Gate 3 quality_checks gains every_story_has_epic.

v2.3.0 2026-05-21 MINOR
  • Pipeline timing instrumentation + /pipeline-timing report. Every step now records started_at and completed_at to _pipeline-state.json → step_timings; gate steps additionally record presented_at / approved_at so the report can quantify how long each gate sat waiting on the PM. The report distinguishes wall-clock total (full elapsed, includes gate waits and breaks) from active-work total (model working time, gate waits excluded), and includes a per-step breakdown plus a per-gate table. Automatically embedded at the top of the Step 12 transcript and on the Confluence parent hub page; also callable standalone via /pipeline-timing. Falls back to JSONL parsing for un-instrumented steps and marks inferred rows with ~.
  • New Step 12: Export Conversation Transcript. Reads the live Claude Code session JSONL and writes the full PM↔model conversation for the feature's pipeline window to two markdown files: [feature]-transcript-clean.md (readable back-and-forth) and [feature]-transcript-full.md (with tool calls + system events for forensic debugging). Model thinking blocks are excluded. Prior exports are timestamp-suffix-renamed rather than overwritten. Auto-runs at end of /build-product; also callable any time via /export-transcript.
  • Confluence Publish now writes the entire feature workspace. Parent hub page + one numbered child page per artifact: Step 1: Research, Step 2: Codebase Review, Step 3: PRD, Step 4a/4b: Product / Technical Review, Step 6: System Design, Step 7: Visual Diagram (Figma embed), Step 8: Design Catalog — Phase [N], Step 10: User Stories Breakdown, Step 10½: Timeline (Figma embed + link to HTML Gantt).
  • Per-file mtime change detection. Each artifact's source-file modification time is compared to the last published mtime in _pipeline-state.json → confluence_hub.artifacts. Only pages whose source actually changed are re-published; unchanged pages are skipped (existing version preserved). The parent hub is always updated to keep status fresh.
  • New /publish-to-confluence command. The older /prd-to-confluence slash command and its underlying subprompt file were removed in this release — the command publishes nine artifacts, not just the PRD, so the old name was actively misleading. The subprompt was renamed to subprompts/publish-to-confluence.md.
  • Legacy migration on first run. Features with a pre-v2.3.0 single-PRD Confluence page are offered a one-time migration: the legacy page is reparented under the new hub as Step 3: PRD, preserving its URL so existing bookmarks keep working.
  • /read-feedback and /share-for-review adapted. Feedback can now be pulled from every child page (grouped by source page so PRD comments edit the PRD file, design comments edit the design catalog, etc.). Share defaults to the hub URL with an option to narrow to one specific child.
