00
Intake — Stage 0.5 Auto

Captures everything the pipeline needs before any artifact is produced. The skill asks 7 questions: feature name, Jira project, Jira ticket conventions (open-ended probe with examples — labels, title format, BE/FE split, custom field defaults, fields to leave blank, link conventions), tech stack, product type, permission model, and backend/API surface. Answers persist to _pipeline-state.json → intake and are read by downstream steps. If a prior feature exists in the workspace, the skill offers to reuse its intake.

Dual Review Parallel

Two isolated sub-agents (Claude Agent tool) run simultaneously — not role-switching. 4a Product Reviewer: document quality, problem-solution fit, UX gaps, missing states. 4b Technical Reviewer: reads both the PRD and the codebase review — architecture, data model, API contracts, security, HIGH risks.

Results synthesized: agreements applied, single-source findings logged, conflicts converted to conflict cards for Gate 1.

⏸ Pipeline pauses here. Review the PRD. Say "approved" or give feedback.

Applies all review findings to the PRD. Then runs ~5 automated quality checks before presenting the gate: problem statement specificity, measurable outcomes, HIGH risks resolved, success metric baseline, codebase risk coverage. Conflict cards must be resolved.

Supports conditional approval. Say "approved with conditions: [list]" to advance now and track conditions in _open-conditions.md — verified at Gate 2.

Design Prompts — v0 / Figma Make Auto

Generates one structured design prompt per screen. The same prompt works in both v0 and Figma Make — PM chooses the tool. Prompts include: context, layout, content list, all four states (default, empty, loading, error), and optionally component references for Figma Make. Full screen inventory validated against PRD user stories.

📁 design/[feature]-phase-[N]-designs.md
G2
Update PRD from Designs → Gate 2: Designs Approval Gate
⏸ Pipeline pauses here. Review the design catalog. Say "approved" or give feedback.

Syncs the PRD with the finalized design catalog: design catalog reference, copy/flow changes, AC updates, decision log entries. Quality checks: diagram coverage, UI state coverage (empty/loading/error/populated), Gate 1 conditions resolved.

📁 prd/[feature]-prd.md (updated in place)
G3
User Stories Breakdown → Gate 3: Breakdown Approval Gate
⏸ Pipeline pauses here. Review the breakdown. Once approved, Jira tickets are created.

Generates exhaustive Gherkin acceptance criteria, FE/BE story pairing, testing notes, and a Build Sequence Map. Multi-epic grouping (v2.4.0+): proposes an Epic split (one per PRD phase by default, sub-epics for functional clusters); PM accepts or adjusts before stories are composed. Wave sequencing (v2.10.0+): computes a Wave assignment for every story via topological sort on dependencies — waves group stories that can ship in parallel; Wave Summary section lists what ships together; cycles in the dependency graph are CRITICAL findings, refuse to advance until PM resolves. DRAFT mode (v2.4.0+): if designs aren't finalized yet, the PM can write stories from the PRD alone — design-dependent stories tagged Status: DRAFT — needs design, sized with *, exempt from UX state coverage at Gate 3, labeled draft in Jira. 11 automated quality checks at Gate 3.

Optional after approval: publish breakdown to Confluence + share in Slack for engineering sizing review before Jira tickets are created.

DRAFT refresh: when designs land later, /change-mode → "Designs arrived" walks through every DRAFT story with the new designs, refreshes AC + sizing + UX coverage, and updates the Jira tickets in place (removes the draft label).

📁 user-stories/[feature]-user-stories.md
10½
Timeline (Gantt) Auto

Produces a Gantt-style timeline at the Epic + Phase level (not story level). Hybrid estimation: the skill proposes durations from the user-stories breakdown's Size column × default velocity (8 person-days per dev per sprint), then the PM tunes any epic or phase. Two outputs every run: Figma FigJam timeline (via Figma MCP — URL stored in _pipeline-state.json) and an editable interactive HTML Gantt (v2.5.0+: drag bars to shift dates, drag right edge to resize duration, downstream bars auto-cascade — hold Shift to lock; vanilla JS, no CDN, opens offline; localStorage auto-save). Honest target-gap math: if the computed end exceeds a PM-supplied target launch, the step surfaces the gap and offers scope cut / team increase / slip — it does not silently shrink durations.

Round-trip edits in two steps (v2.6.0+): Chrome/Edge users click 💾 Save to skill — the HTML writes the plan JSON directly into the feature's timeline/ folder via the File System Access API (first click grants permission; subsequent clicks save silently to the same file via a persisted FileSystemHandle in IndexedDB). Then in chat: /timeline apply — no path needed, the command auto-discovers the latest plan JSON in timeline/ or ~/Downloads/. Skill shows a diff, updates _pipeline-state.json, re-renders the sidecar + HTML so applied edits become the new baseline. Safari/Firefox fall back to ⬇ Export Plan (download flow); auto-discovery picks up Downloads files automatically. Schema-gated, idempotent, logged to timeline.applied_edits[].

11
Export Parallel

Three parallel export agents. Jira (always): creates one Epic per multi-epic grouping (v2.4.0+) with each Epic's description scoped to its own stories; the PRD + breakdown files attach to every Epic. Then creates one ticket per user story with ADF user story, verbatim Gherkin AC, Testable field, FE/BE labels, sequence labels (seq-01…), size labels, and Relates-to linking for FE/BE pairs. DRAFT stories get a draft label for downstream queryability. Deduplication check prevents re-runs from creating duplicates. Drive (optional): mirrors the entire feature folder, generates a _FEATURE_SUMMARY.md. Confluence (optional, v2.8.0+): publishes the stakeholder-relevant artifacts as a parent hub page + numbered child pages: Research, Codebase Review, PRD, System Design, Visual Diagram, Design Catalog (per phase), lightweight User Stories index (links to each Jira Epic — no full Gherkin), and Timeline. Per-file mtime change detection. Product/Technical Reviews and the full Gherkin breakdown stay local.

🎫 Jira Epic + tickets
📁 jira-export/[feature]-jira-manifest.md
☁️ Drive folder (if enabled)
📖 Confluence page (if enabled)

Export Conversation Transcript Auto

Reads the live Claude Code session JSONL (~/.claude/projects/-Users-judydarvin/[session-uuid].jsonl) and writes the full PM↔model conversation for this feature's pipeline window to two markdown files. Clean version: user messages + assistant text only — the readable back-and-forth. Full version: same conversation plus tool calls and (truncated) tool results, with system reminders and permission events included for forensic debugging. Model thinking blocks are excluded from both files (private reasoning). Prior transcript exports are timestamp-suffix-renamed rather than overwritten, so every run is preserved. Skippable per-run via "skip transcript" at the end of Step 11; also callable any time via /export-transcript.

v2.18.0 2026-05-29 MINOR
  • No inline change history in artifacts — enforced by heading name. Reader docs can no longer carry a ## Change log, ## Changelog, ## Revision history, ## Refactor history, or ## Refactor summary section (by any wording), nor **v0.X (date):** version blocks or "Document version" / "Last updated" stamps. A version number in the title line plus a one-line changelog pointer is all an artifact carries.
  • Centralized changelog grouped by artifact. changelog/[feature]-changelog.md is one feature-level file with a ## section per artifact (PRD, System Design, User Stories Breakdown, Design Catalog, Timeline, Decision Log…), each append-only and dated. Each /change-mode run writes one dated line under every artifact it touched.
  • Decision log moved out of the PRD into a sidecar. Locked decisions now live in decisions/[feature]-decision-log.md — the PRD's § 10 is a one-line pointer. Every producer (create-prd, apply-fixes, update-prd-from-designs, read-feedback, conflict resolution, change-mode) appends to the sidecar; every consumer (validate-prd, exec-summary, review-prd, publish-to-confluence, self-checks) reads from it.
  • Two leaks closed + new check. User Stories Appendix B ("Refactor history / changelog") is now a one-line pointer; /pull-from-figma no longer writes a ## Change log into the stories file; /validate-user-stories Check 8b flags inline change history anywhere in a breakdown. New decisions/ folder in the output tree and Drive mirror.

v2.15.0 2026-05-25 MINOR
  • /publish-to-confluence — pre-flight drift + comment check. Every page resolving to update now runs three lightweight MCP calls in parallel before the publish plan is presented: getConfluencePage (drift), getConfluencePageInlineComments (orphan risk), getConfluencePageFooterComments (safe — context only). Catches the silent-overwrite + orphaned-anchor failure modes the skill had since v2.0.
  • Drift detection. Compares Confluence's version.number against last_published_version in state. When Confluence is higher (= someone edited outside the skill), flags 🚨 DRIFT (v[N] > last-published v[M]) in the publish plan. Drift never auto-resolves — explicit PM choice required.
  • Inline comment surfacing. Inline comments are anchored to specific text in the body. updateConfluencePage may orphan them when the anchored text changes between composition runs. Pre-flight surfaces ⚠ N inline + M footer with author + anchor-text excerpt per comment so the PM can see exactly what's at risk before deciding to overwrite. Footer comments survive automatically — surfaced for context, not gating.
  • Per-page resolution actions. For each flagged page: proceed (overwrites; drift + anchors may go), skip (don't update this run; state preserved so next run re-prompts), pull-comments (write a structured dump to confluence-feedback/[YYYY-MM-DD]/[step-N]-comments.md and skip publish — non-destructive path), show-drift (unified diff of current Confluence body vs about-to-publish body), show-comments (full thread bodies, no extra API call).
  • Sidecar dump format. confluence-feedback/[YYYY-MM-DD]/[step-N]-comments.md with structured per-comment blocks (author, date, anchor text, body, status, replies). For Step 3 PRD specifically, sidecar includes a pointer line to run /read-feedback for auto-synthesis. For other artifacts, read-and-edit-by-hand.
  • New state field last_published_version per artifact. Captured from every successful create/update API response and persisted under confluence_hub.artifacts.[key].last_published_version (plus on the parent hub). Legacy state files without it are treated as last_published_version = 0 — first post-upgrade run never triggers a false drift alarm.

v2.11.0 2026-05-22 MINOR
  • New /exec-summary standalone command. Synthesizes a feature's PRD + system design + user-stories breakdown + timeline + decision log into a single ~20 KB / 5–7 PDF page executive summary using a fixed 9-section structure (vision, use cases, moving pieces, teams & roles, timeline alignment, open decisions, risks, the ask, what's next). v2.10.0 2026-05-22 MINOR
  • Wave sequencing in the User Stories Breakdown. New Step 2.5 — Wave Sequencing in ai-framework/06-user-stories.md computes a Wave assignment for every story via topological sort on the Depends On column. Wave 1 = stories with no dependencies; Wave N = stories whose dependencies are all in Waves 1..N-1. Global numbering (W1, W2, ... W[N]) — not reset per phase or epic.
  • Cycles in the dependency graph are CRITICAL findings. The step detects cycles and refuses to advance Gate 3 until the PM resolves. Catches the class of bug where engineering can never start because every starting point depends on something else.
  • Build Sequence Map gains a Wave column (between Phase and Depends On). FE/BE pairs in the Related To column are NOT treated as hard dependencies by default — pairs commonly land in the same wave.
  • New Wave Summary section in the breakdown file lists what ships in each wave (theme + story_ids), with explicit annotations for the critical convergence wave (unlocks a large downstream block) and the launch gate wave (last before release).
  • State schema adds user_stories.waves[]. Two new Gate 3 quality checks: every_story_has_wave and dependency_graph_acyclic. Closes the loop with /validate-user-stories Check 7 (which already expected waves to exist).

  • /validate-prd checks: (1) internal consistency between sections (data model vs API contracts, scope vs phases, decision log vs body); (2) hallucinated data — claims without sources, cross-checked against the research output; (3) completeness — [TBD] / [TODO] / empty sections; (4) VOC traceability — does the PRD use research language or generic AI prose?; (5) NFR measurability — concrete thresholds vs vague aspirations; (6) scope coherence — in-scope vs out-of-scope contradictions, scope-creep references.
  • /validate-user-stories checks: (1) story↔PRD traceability — every story maps to a PRD section, no orphans; (2) AC duplication / contradiction across stories; (3) FE/BE pair coherence — endpoint contracts, naming, permissions match; (4) AC specificity — catches lazy "when clicked, it works" Gherkin; (5) sizing sanity — scenario count + surface count vs size label; (6) DRAFT consistency between state and the breakdown; (7) wave / dependency sanity — acyclic, correctly ordered.
  • Same UX as /pipeline-doctor: inline summary → per-finding walkthrough with approve/skip → full timestamped markdown report saved to [feature]/validation/[feature]-validate-{prd|stories}-[YYYY-MM-DD-HHMM].md. History log accumulates one-line entries per run.
  • Why this matters: the doctor catches structural drift (missing files, schema problems); these validators catch content drift — a PRD that no longer agrees with itself after 17 review-and-fix cycles; a 75-story breakdown where two stories specify different copy for the same screen; an L-sized story that's actually 3 trivial scenarios. Invisible to mechanical gate quality checks and to skim-reading.
  • Cost note: /validate-user-stories is the most expensive command in the skill. On a 614KB breakdown (like nestfully-ai), expect 1–3 minutes runtime.

v2.7.0 2026-05-22 MINOR
  • New /pipeline-doctor diagnostic command. Scans the skill itself and feature workspaces for drift, inconsistencies, and stalls. Four check categories: (A) skill self-consistency — every step in pipeline-configs.yaml has matching prose in SKILL.md and subprompts/build-product.md, every quality_check is defined, every instruction file exists, every step block has an explicit "Next:" handoff; (B) feature-state consistency — _pipeline-state.json schema validity, artifact-path existence on disk, gate-state coherence, DRAFT/epic/Confluence cross-checks; (C) slash command coverage — every subprompts/*.md has a registered command, no broken pointers; (D) stale features — pipelines >30 days without completion, state files unchanged for 14+ days.
  • Read-only by default with per-finding fix approval. The doctor scans and reports; it doesn't modify any file until the PM approves a specific fix at the per-finding walkthrough. Concrete fix suggestions per finding (file path + change to make).
  • Timestamped reports. Every run writes a full markdown report to _pipeline-doctor-report-[YYYY-MM-DD-HHMM].md at the workspace root and appends to _pipeline-doctor-history.md.
  • The class of bug it catches: orchestrator drift where new steps land in pipeline-configs.yaml but never get added to subprompts/build-product.md — exactly the failure mode that caused the v2.2.0 Step 10.5 / v2.3.0 Step 12 silent stalls (fixed in the prior commit).

v2.3.0 2026-05-21 MINOR
  • Pipeline timing instrumentation + /pipeline-timing report. Every step now records started_at and completed_at to _pipeline-state.json → step_timings; gate steps additionally record presented_at / approved_at so the report can quantify how long each gate sat waiting on the PM. The report distinguishes wall-clock total (full elapsed, includes gate waits and breaks) from active-work total (model working time, gate waits excluded), and includes a per-step breakdown plus a per-gate table. Automatically embedded at the top of the Step 12 transcript and on the Confluence parent hub page; also callable standalone via /pipeline-timing. Falls back to JSONL parsing for un-instrumented steps and marks inferred rows with ~.
  • New Step 12: Export Conversation Transcript. Reads the live Claude Code session JSONL and writes the full PM↔model conversation for the feature's pipeline window to two markdown files: [feature]-transcript-clean.md (readable back-and-forth) and [feature]-transcript-full.md (with tool calls + system events for forensic debugging). Model thinking blocks are excluded. Prior exports are timestamp-suffix-renamed rather than overwritten. Auto-runs at end of /build-product; also callable any time via /export-transcript.
  • Confluence Publish now writes the entire feature workspace. Parent hub page + one numbered child page per artifact: Step 1: Research, Step 2: Codebase Review, Step 3: PRD, Step 4a/4b: Product / Technical Review, Step 6: System Design, Step 7: Visual Diagram (Figma embed), Step 8: Design Catalog — Phase [N], Step 10: User Stories Breakdown, Step 10½: Timeline (Figma embed + link to HTML Gantt).
  • Per-file mtime change detection. Each artifact's source-file modification time is compared to the last published mtime in _pipeline-state.json → confluence_hub.artifacts. Only pages whose source actually changed are re-published; unchanged pages are skipped (existing version preserved). The parent hub is always updated to keep status fresh.
  • New /publish-to-confluence command. The older /prd-to-confluence slash command and its underlying subprompt file were removed in this release — the command publishes nine artifacts, not just the PRD, so the old name was actively misleading.   • /read-feedback and /share-for-review adapted. Feedback can now be pulled from every child page (grouped by source page so PRD comments edit the PRD file, design comments edit the design catalog, etc.). Share defaults to the hub URL with an option to narrow to one specific child.
