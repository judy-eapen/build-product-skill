# Reopen Gate 2

Re-open the **Design approval gate** for an existing feature.

Use this when:
- After approving Gate 2, the designs turn out to be wrong or incomplete (missing screens, wrong flows, inconsistent with PRD).
- Designs were approved but a designer or stakeholder requests substantive rework.
- The PRD has been updated since Gate 2 and the designs no longer match.

Read and follow Error Type 1 in `ai-framework/error-handling.md`.

## What this command does

1. **Identify the feature.** Ask the PM which feature folder to re-open Gate 2 for. Confirm the path: `~/Desktop/Resources/PDLC Workflow Docs/[feature-name]/`.
2. **Flag downstream artifacts as DRAFT.** Every file produced after the original Gate 2 approval gets a `STATUS: DRAFT — Gate 2 reopened on [date]` header line added to the top:
   - Updated PRD (post-design sync)
   - User stories breakdown
   - Jira manifest
   - Any in-flight tickets in Jira (flag in description, do not delete)
3. **Re-run Steps 6–9** (System Design optional → Visual Diagram → Design → Update PRD from Designs) using the existing artifacts as starting context:
   - Ask the PM what specifically needs to change in the designs.
   - Update only the affected screens / flows / states. Do not regenerate untouched designs from scratch.
   - Re-sync the PRD from the updated design catalog.
4. **Re-present Gate 2** with a full quality check.
5. **On approval**: update the pipeline state file. DRAFT-flagged downstream artifacts remain DRAFT until regenerated by re-running Steps 10+ or until the PM explicitly marks them current.

## What it will NOT do

- It will not regenerate every design from scratch. Surgical updates only.
- It will not auto-trigger Gate 3 re-approval. After Gate 2 is re-approved, the PM decides whether to re-run the User Stories Breakdown or use `/reopen-gate-3` separately.
- It will not modify Jira tickets directly. If tickets are affected, the prompt advises the PM to use `/change-mode` after the re-approval to propagate diffs.

## Related commands

- `/reopen-gate-1` — re-open the PRD approval gate (for fundamental PRD issues).
- `/reopen-gate-3` — re-open the User Stories Breakdown approval gate.
- `/change-mode` — propagate a smaller change without reopening a gate.
