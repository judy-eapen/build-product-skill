# Reopen Gate 1

Re-open the **PRD approval gate** for an existing feature.

Use this when:
- After approving Gate 1, you realize the PRD has a substantive flaw (missing scope, wrong user, fundamental misread of the problem).
- A patch via `/change-mode` isn't enough — the PRD itself needs to be re-reviewed.
- New research has changed the problem statement.

Read and follow Error Type 1 in `ai-framework/error-handling.md`.

## What this command does

1. **Identify the feature.** Ask the PM which feature folder to re-open Gate 1 for. Confirm the path: `~/Desktop/Resources/PDLC Workflow Docs/[feature-name]/`.
2. **Flag all downstream artifacts as DRAFT.** Every file produced after the original Gate 1 approval gets a `STATUS: DRAFT — Gate 1 reopened on [date]` header line added to the top:
   - System design (if any)
   - Visual diagram
   - Design catalog
   - Updated PRD (after design sync)
   - User stories breakdown
   - Jira manifest
   - Any in-flight tickets in Jira (flag in description, do not delete)
3. **Re-run Steps 1–5** (Research → Codebase Review → Create PRD → Dual Review → Apply Fixes) using the existing artifacts as starting context, not from scratch:
   - Re-read the original research summary and codebase review.
   - Ask the PM what specifically needs to change in the PRD.
   - Apply changes; re-run the Dual Review agents in parallel; apply fixes.
4. **Re-present Gate 1** with a full quality check (10 automated signals).
5. **On approval**: update the pipeline state file. DRAFT-flagged downstream artifacts remain DRAFT until they're regenerated by re-running Steps 6+ or until the PM explicitly marks them current.

## What it will NOT do

- It will not delete or overwrite the DRAFT-flagged downstream artifacts. They stay on disk with the DRAFT header so the PM has a record of what was previously approved.
- It will not auto-cascade through Gate 2 / Gate 3 reapprovals. After Gate 1 is re-approved, the PM decides whether to re-run downstream steps or use `/reopen-gate-2` separately.
- It will not modify Jira tickets that were already created. If tickets are affected, the prompt advises the PM to use `/change-mode` after the re-approval to propagate the diffs.

## Related commands

- `/reopen-gate-2` — re-open the Designs approval gate.
- `/reopen-gate-3` — re-open the User Stories Breakdown approval gate.
- `/change-mode` — propagate a smaller change without reopening a gate.
